# 万象维护与交接

第一次接手从[当前进度](STATUS.md)开始。它记录最近一次确认的发布版本、已验收的工作和仍未收尾的问题。[下一步](NEXT.md)说明接下来从哪里改，怎样判定完成。

| 文档 | 用途 |
| --- | --- |
| [当前进度](STATUS.md) | 确认当前发布、阶段状态和可复查的验收证据 |
| [下一步](NEXT.md) | 查看待办顺序、相关代码和验收条件 |
| [接手指南](HANDOFF.md) | 在新电脑上拉取、构建及测试，定位代码与发布入口 |
| [长期开发总纲（Word 原件）](omnora-development-plan.docx) | 查看产品愿景、目标架构及版本规划，优先阅读第 2、31、38、40、41 章 |
| [路线图](../../ROADMAP.md) · [架构](../ARCHITECTURE.md) · [测试记录](../TESTING.md) · [安全边界](../SECURITY.md) | 查阅功能清单、接口约定、历史验收与实现边界 |

Word 总纲的建设基线是 0.9.0。里面的里程碑和候选方案会随开发推进，当前实现以进度页、仓库代码和对应版本的验收记录为准。

## 每轮结束时更新什么

- 改动到哪个阶段，在[当前进度](STATUS.md)记录日期、版本或分支、已完成内容和剩余缺口。同一轮的提交可由 Git 历史定位，发布后补链接到固定提交、标签或 CI。
- 在[测试记录](../TESTING.md)留实际运行命令、环境、通过／失败／跳过情况，以及可复查的 CI 或样本。只有走通对应场景，才把该场景标为已验收。
- 更新[下一步](NEXT.md)的首项和完成条件。构建命令、工具链或目录变化时，同步更新[接手指南](HANDOFF.md)。

每项任务保留一条清晰的状态，例如「待做」「已实现，待验收」「已验收」「已发布」。遇到阻塞时，写下失败的环节和恢复所需的信息。把交接文档和相关改动一起提交，下一位维护者就能从同一条 Git 历史旁证。
