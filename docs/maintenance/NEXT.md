# 下一步

## 先做 · 0.9.3 剩余进程管理

- [ ] **复现和定位退出残留。** 从 [controller.cpp](../../desktop/controller.cpp)、[inspectionrunner.cpp](../../desktop/inspectionrunner.cpp) 和 [worker 的外部引擎调用](../../worker/formabox/core.py) 入手。用测试样本分别走任务执行、预览和引擎探测，记录关闭窗口、点击取消和超时三种情形的父子进程状态。
- [ ] **回收本次任务所属的进程树。** 按长期总纲评估 Windows Job Object 的接入点与兼容处理。保持现有协作式取消，在超时后再终止所属进程树。先测实际外部引擎和取消重跑，确认其他任务、其他万象实例及用户已打开的程序能继续运行。
- [ ] **完成异常退出诊断和回归。** 将启动失败、主动取消、超时和异常退出区分到任务记录。真实 Windows 验收应覆盖关闭后无所属子进程残留、原件保留、暂存结果不会误报成功，以及重跑不会重复提交或覆盖已有产物。

## 接着做 · 0.9.4 安装升级

- [ ] **先建立旧版升级样本。** 用已发布的 0.9.0 和 0.9.3 安装包构建测试环境，放入可验证的合成配置、预设、历史和输出文件。
- [ ] **实现覆盖升级与失败回滚。** 从 [NSIS 安装脚本](../../packaging/windows/installer.nsi) 和[安装包验收脚本](../../scripts/test-windows-installer.ps1) 入手，规划旧版识别、文件替换、日志与用户数据保留。验证中文和空格路径、旧版升级中断、失败后旧版恢复启动、升级成功后正常卸载。
- [ ] **扩展真实安装流程的 CI 验收。** 验收安装版能启动并读取升级前的数据，失败回滚后可继续使用旧版，再更新进度页和发行说明。

待上述工作通过验收后，再根据[长期开发总纲](omnora-development-plan.docx)与[路线图](../../ROADMAP.md)确定 1.0 稳定核心的下一批工作。
